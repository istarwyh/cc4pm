# Lesson 24.12: DigUp——本地多模态搜索与片段定位的产品设计

## 为什么“找到文件”还不够

你记得“某个播客聊过睡眠”，却不记得文件名；即使找到了两小时录音，仍然需要拖进度条。

[DigUp](https://github.com/ARahim3/DigUp) 把自然语言查询变成照片、PDF 页、录音片段、视频时刻和代码行的入口。它的产品价值可以写成：**描述你记得的内容 → 看见命中证据 → 从相关位置继续工作**。

本课依据 2026-10-30 核对的上游提交 `dc2651ad8299160bbe91e972f857e1a1599a8419`。这是文档与源码案例；以下练习需要你在自己的设备验证，不代表本课已实测所有平台或中文效果。

## 学习目标

- 理解统一向量空间怎样支持跨模态搜索，以及它与生成式问答的区别
- 解释页码、时间戳和代码行号如何贯穿索引、结果和打开动作
- 拆解首次索引、键盘操作、弱结果和跨平台降级的产品设计
- 通过小型测试集检验语义搜索、精确匹配、定位和离线边界
- 判断 DigUp、QMD 和 graphify 在个人知识工作台中的分工

## Step 1：先分清模型与产品

[Google 官方模型卡](https://huggingface.co/google/embeddinggemma-2) 将 EmbeddingGemma 2 描述为 740M 参数的多模态嵌入模型，支持文本（含代码）、图像、音频和视频，统一映射到 768 维空间，支持 100 多种语言，采用 Apache 2.0 许可证。

它输出向量，不直接回答“合同允许养宠物吗”。DigUp 负责文件解码、切片、索引、排序、预览和打开原文件；应用本身采用 MIT 许可证。不要把模型支持的输入，自动等同于每个平台完整实现的功能。

```text
你选择的目录
  → 文件读取器：图片 / PDF 页 / 文本段 / 音频窗口 / 视频帧
  → llama.cpp 运行 EmbeddingGemma 2，生成片段向量
  → SQLite：文件信息 + 片段位置 + 向量 + 全文索引

你的查询 → 文本查询向量 + 精确词匹配
  → 排序与文件聚合 → 展示命中片段 → 打开原文或播放
```

DigUp 使用约 865 MB 的量化模型文件，包含文本部分及图像、音频编码器。索引由独立 helper 进程完成，结束后退出；搜索只需加载文本部分。**把首次重计算与日常轻交互分开**，是这类产品能常驻桌面的关键。

## Step 2：把“位置”作为数据的一部分

你不能只保存“这个视频与斑马相关”。检索单元必须带着它在文件里的位置。

| 内容 | DigUp 的切分方式 | 命中后的位置 |
|------|-----------------|--------------|
| 照片、截图 | 图片向量；Mac 额外读取截图文字供精确匹配 | 文件 |
| PDF | 逐页文本；文字很少的页作为图片处理 | 页码 |
| 文档、表格、幻灯片 | 文本段；表格包含表名和行，幻灯片包含备注 | 文本片段 |
| 音频 | 30 秒窗口，每 25 秒前进一次 | 窗口起始时间 |
| 视频 | 每 3 秒采样并去除近似重复帧，另索引音轨 | 帧或音频窗口的时刻 |
| 代码 | 按完整行切成最多约 1,800 字符的片段 | 行范围；笔记本为单元格 |

这些数值是本次核对版本的实现配置，不是模型或所有检索产品的通用限制。

源码中 `files` 表保存文件信息，`segments` 表包含 `kind`、`modality`、`loc`、`loc_end`、`excerpt` 与 `vec`。同一个 `loc` 的单位取决于片段类型。你设计自己的接口时，要把类型和单位一起返回，不能只给一个裸数字。

```json
{
  "file": "interview.mp4",
  "segment_kind": "audio",
  "location": { "unit": "seconds", "start": 75, "end": 105 },
  "action": "preview-at-location"
}
```

上面是教学用契约示例，**不是 DigUp CLI 的真实输出 schema**。

### 为什么不能承诺“斑马出现的第一秒”

抽帧可能漏掉短暂画面；30 秒窗口可能从话题出现前开始。这里的定位是**相关片段入口**，不是逐帧事件检测或逐字转录对齐。你应该验证命中位置附近是否包含目标，并记录偏差，而不是只看返回了时间戳。

不同播放器也会影响打开效果。上游文档说明，Windows / Linux 的 VLC、mpv、MPC-HC 等可接受时刻参数；不支持定位的外部程序可能从头播放，应用内大预览仍可从命中位置播放。Mac 的 QuickTime / IINA 以及 PDF 打开行为也有各自适配。文档片段展示不等于所有编辑器都能跳到对应字符。

## Step 3：语义检索与精确匹配各有任务

搜“海边的狗”适合向量相似度，搜发票编号 `INV-2047` 则要保留原字符串。

DigUp 同时使用向量与 SQLite 全文索引：按模态校准语义分数，加入文件名和正文中的词匹配；对编号、错误码一类查询提高精确匹配的权重，再按文件展示最佳片段。不能把不同模态的原始相似度直接当成可比较的置信度。

产品上有两个值得借鉴的细节：

- 低于最佳分数一半的结果折叠到 weaker matches。它是展示规则，不是“低于 50% 概率就不相关”。
- 代码默认关闭，选择目录后独立建索引，用 `code:` 查询，结果不混入日常文件搜索。不同任务可以共享模型，同时隔离检索范围和排序。

索引规模也决定架构。DigUp 在 SQLite 存储半精度向量，搜索时用内存矩阵比较；个人资料规模下先测量这条简单路径，不必一开始引入独立向量数据库。向量的模型、版本和切分配置必须一致；模型或配置改变后不能无条件复用旧索引。

## Step 4：拆解能迁移的产品设计

以下“迁移建议”是从 DigUp 行为提炼的课程设计练习，不是上游额外承诺的功能。

| 用户的阻力 | DigUp 的设计 | 你可以迁移的原则 |
|------------|--------------|------------------|
| 不知道导入全盘要多久 | 选目录时显示文件类型数量与本机耗时估计，可选子目录 | 先展示成本，再让用户开始 |
| 下载时只能干等 | 模型在设置过程中后台下载，持续展示进度 | 并行安排准备动作，解释等待 |
| 全量索引太慢 | 文件名先可搜，优先新文件；长 PDF 首批处理后再补余下页 | 先交付部分可用结果，标明覆盖范围 |
| 搜到文件还要翻找 | 结果带页码、时刻或行号，并在该位置预览 | 以“继续工作”作为闭环 |
| 每次切换 App 很打断 | 全局快捷键、上下键、Enter 打开、Space 预览，大窗口提供网格和筛选 | 高频任务优先键盘闭环 |
| AI 结果看起来都很确定 | 折叠弱匹配，允许回原文件检查 | 让用户看到证据并复核 |
| 不愿把私人目录交给 AI | 显式选目录、排除目录、代码另开开关 | 数据范围本身就是产品界面 |

注意跨平台能力：当前 Windows / Linux 是 beta，截图文字 OCR 尚未支持，旧 `.doc`、RAW、SVG 读取也与 Mac 有差异。你的需求表应写“平台 × 内容 × 打开动作”，而不是一个笼统的“全平台支持”。

## Step 5：按真实边界验证“本地优先”

上游说明：不需要账号，不上传索引内容，没有遥测；首次下载模型需联网，默认每天检查更新，可在设置关闭。**模型准备完成后，索引与搜索可以离线运行**，不应宣传为“从安装到更新都不联网”。

还有两个与产品直接相关的边界：

1. SQLite 索引保存路径、提取文字和向量，应用不自行加密索引。离线不代表没有本地敏感副本；普通文本中的秘密也不能指望文件过滤器全部识别。
2. 在云端 Claude 会话中粘贴检索结果，会形成新的数据传输。DigUp 本地执行，不代表你把它接到任意 Agent 后仍然全程离线。

练习时只选测试目录，不选个人全盘。移除测试目录后检查搜索结果是否消失。用断网搜索验证离线可用；若要验证“不上传”，还需要检查网络活动，仅凭断网时可搜索不足以证明此前没有外发。

## 实操 A：跑通从查询到原片段

1. 从 [上游 Releases](https://github.com/ARahim3/DigUp/releases) 下载对应平台版本。Mac 需要 Apple Silicon 和 macOS 14+；Windows / Linux 的要求与 beta 状态以下载说明为准。
2. 准备小型自建目录：一张动物照片、一份含明确条款的两页 PDF、一段你录制的睡眠话题音频、一段目标只在中段出现的视频。
3. 首次启动完成模型下载，只选择该目录，记下预计耗时、实际耗时和索引完成状态。代码练习另选一个无密钥的示例仓库并开启代码搜索。
4. Mac 用 `⇧⌘Space`，Windows / Linux 用 `Ctrl+Shift+Space` 唤起搜索。依次试内容描述、PDF 原句、音频话题、视频画面。
5. 上下键选择结果，Space 预览，Enter 打开；对照原文件，记录页码与时间偏差。外部程序不能定位时，分别记录外部打开和内部预览的行为。
6. 关闭更新检查，断网重启应用后重复查询，再移除目录检查清理结果。

先用英文示例建立基线，再测试中文和同义改写。模型支持多语言不等于每种语言效果相同；上游评估覆盖英语、孟加拉语和阿拉伯语，不能直接据此推导中文效果。上游还说明中日韩等无空格语言的精确词切分存在限制。

## 实操 B：用 CLI 接入工作流，不虚构 MCP

DigUp 自带 `digup` helper，提供搜索和 JSON 输出。它不是一个需要照搬成 Skill 的提示词包，也不需要为了接 Agent 先假设它有 MCP。

Mac 安装后的实际调用示例：

```bash
DIGUP_BIN="/Applications/DigUp.app/Contents/Helpers/digup"
"$DIGUP_BIN" --help
"$DIGUP_BIN" status
"$DIGUP_BIN" search "a dog on the beach" --kind image,video -n 5
"$DIGUP_BIN" search "where they talk about sleep" --json
"$DIGUP_BIN" search "code: retry a failed call with backoff" --json
```

Linux 的 .deb helper 路径为 `/usr/lib/DigUp/helper/digup`；其他安装包从其 helper 目录定位可执行文件，先看 `--help`。不要假定安装桌面应用后 `digup` 已在 PATH 中。

`search`、`status`、`estimate` 可与应用同时运行。**不要对应用正在使用的索引运行 `digup index`**；独立实验需用 `--index` 指向另外的目录。

如果你写自己的调用 Skill，遵循 Lesson 24.11：Skill 定义范围、查询、展示与验收，CLI 提供检索能力。先读取真实 JSON，再决定怎样提取路径和位置；不要把教学契约示例硬套到实际返回值。目录索引与打开程序都需要明确的目标范围。

## 实操 C：把产品主张写成验收表

下面是你自建测试集的模板，不是上游已跑出的成绩：

| 查询类别 | 测试输入 | 必须核对的证据 |
|----------|----------|----------------|
| 视觉语义 | “视频里的斑马”及同义表达 | Top 5 是否含正确视频，位置附近是否真有目标 |
| 语音语义 | “聊睡眠的地方” | 音频窗口是否覆盖话题，偏移多少秒 |
| PDF 条款 | “租约里养宠物的条款” | 正确文件、正确页、条款可见 |
| 精确匹配 | 测试文件内唯一编号 `INV-2047` | 返回原编号所在文件，不混淆相似编号 |
| 代码 | `code: retry a failed call with backoff` | 找到实现并定位行范围；普通搜索不混入代码 |
| 无匹配 | 测试集中不存在的内容 | 记录弱匹配展示；不能将相似结果当成事实 |
| 生命周期 | 删除或移除测试文件夹 | 搜索不继续返回旧内容 |

为每条记录版本、平台、索引状态、预期文件与位置、Top 1 / Top 5 命中、定位偏差、冷启动和热查询耗时。漏检时先区分“尚未索引”“解码失败”“切片漏掉目标”“排序不佳”“打开器不支持定位”，再决定修改哪层。

上游 `evals/` 给查询配置期望文件与位置区间，CLI 也提供 `eval`。你可以借鉴这种可复跑评估方式；上游小测试集或开发者机器上的毫秒数，不是你产品的普遍性能承诺。

## FAQ

**Q：已经有 QMD 或 graphify，还需要了解 DigUp 吗？**

需要，它们的主要任务不同：QMD 在本课程中用于本地文本检索；graphify 组织概念关系；DigUp 擅长用内容描述找图片、页和媒体片段。你可先用 DigUp 找原始素材，复核后整理为 Markdown，再交给 QMD / graphify。这里是工作流组合建议，不代表已有自动连接器。

**Q：找到一段录音就能自动生成可靠摘要吗？**

不能。向量检索给出候选片段；摘要还需要读取或转录、核对上下文。使用外部模型时也要重新说明数据流向。

**Q：这次吸收会在我的电脑安装模型或扫描文件吗？**

不会。本课整合资源与产品方法。实际安装、目录选择和本机效果验证属于学习者的操作步骤。
